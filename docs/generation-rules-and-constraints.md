# 《钢铁共和国》整体生成规则与约束

状态：`DRAFT / GOVERNANCE`

适用范围：本文件约束本项目的一切 AI 协作产出，包括设定提案、卷级/章节规划、章节契约、正文生成、扩写、改写、文学复审、状态台账、摘要，以及 Markdown、DOCX、PDF 等交付物的生成与更新。

本文件是统一执行规程，不替代 [项目规则](../AGENTS.md)、[小说创作运行层接入说明](novel-skill-integration.md)、卷内 `AGENTS.md`、Canon 文件或作者的最新明确指令。冲突时，按本文件第 2 节的权威顺序处理。

## 1. 总原则

1. **先保证故事世界是真的，再让文字好看。** 优先解决欲望、阻力、因果、时间压力、代价与后果；不把弱场景润色成更顺滑的弱场景。
2. **Canon 只认已确认的证据。** 草稿、提纲、模型摘要、审稿意见和新点子都不是既成事实。
3. **一章是对世界状态的候选更新，不是独立短文。** 每次生成都必须尊重此前已接受的时间线、人物关系、知识边界、物件归属、资源与伏笔。
4. **保持作品核心。** 创造、责任、修复、连接必须通过人物选择、制度代价和具体行动呈现，不能只作为口号出现。
5. **原创与来源卫生。** 不模仿在世作者的可识别文风；不复制外部作品、提示词、角色示例或无授权文本。可借鉴抽象的方法，不借用具体表达。

## 2. 权威顺序与状态边界

处理任何生成任务时，材料按以下顺序取用；下层不能静默推翻上层。

1. `canon/` 中作者确认的世界、时间线、人物、科技、势力与术语；
2. 作者已批准的章节契约、卷级大纲与事实/人物/时间线/伏笔台账；
3. 明确标注状态的正文、草稿、历史版本与模板；
4. 本轮建议、模型推断、审稿意见和新创意。

| 标签 | 含义 | 可否作为后续既成事实 |
|---|---|---|
| `CANON` | 作者确认的正式设定 | 可以 |
| `ACCEPTED` | 作者明确接受的正文版本 | 可以，并可据此回写持久台账 |
| `OUTLINE` | 已批准的计划义务 | 不可以；它不是已经发生的事件 |
| `DRAFT` | 待审正文或改写候选 | 不可以 |
| `PROPOSAL` | 新设想或候选方案 | 不可以 |
| `TBD` | 证据不足、状态冲突或等待作者决定 | 不可以 |
| `PASS` / `REVIEW` / `BLOCKED` | 审稿结论，不是正文验收状态 | 不能单独升级正文 |

规则：

- `PASS` 只表示当前审查未发现阻塞项，**不等于** `ACCEPTED`。
- 只有作者明确接受后，才可把对应正文标为 `ACCEPTED`，并更新持久事实、人物、关系、知识、资源、伏笔和时间线。
- 若来源状态、适用范围或结论互相矛盾，先登记为 `TBD`，列出证据与待决定事项；不得凭文件新旧、文字篇幅或模型判断自行裁决。

## 3. 当前项目硬门

1. 全书已有四卷、240 章正文草稿；默认工作是**指定章节的独立文学复审**，不是未经授权的批量续写。
2. 第一卷第 118—120 章当前为 `BLOCKED / REPLAN_REQUIRED`。它们不得直接作为第一卷卷末或第二卷开篇的承接依据。
3. 在作者明确选择卷一收束路线前，禁止把第 118—120 章旧稿中的跨区网络、共同框架、手递入口、交接、公共登记、404 低负载在线或北轨新设备，写成当前 P2 链已经成立的事实。
4. 对 `BLOCKED` 章节，允许做证据整理、章节契约重订和方案比较；禁止静默续写、局部粉饰后声称已修复、更新 Canon 或把下游台账当作已生效。

当前阻塞的证据与处理决定以 [第一卷审稿台账](../novel/volume01-waste-iron-camp/review.md) 为准。

## 4. 任务路由

先判定任务类型，再加载最小必要材料；不得把规划、写作、验收混为一次无边界操作。

| 任务 | 允许产出 | 不得做的事 |
|---|---|---|
| 定位/设定 | `PROPOSAL`、世界规则候选、人物卡 | 宣称候选设定已发生 |
| 大纲 | 卷级/章节义务、回收窗口、风险清单 | 把计划事件写入 Canon |
| 章节契约 | 本章目标、约束、承接、代价与结尾扰动 | 用契约代替正文验收 |
| 正文生成 | 标注为 `DRAFT` 的场景/章节 | 自行验收、回写 Canon |
| 改写 | `PATCH`、`REWRITE` 或 `REPLAN` 后的候选正文 | 静默删改下游依赖 |
| 文学复审 | 诊断、证据、风险与建议 | 以审稿意见代替作者决定 |
| 验收后更新 | 带来源哈希的持久变更清单 | 从未接受草稿提取“事实” |

## 5. 生成前最小上下文包

在生成或改写某章前，只读取缺失后会让文本出错的材料，并记录使用版本。最低包含：

1. 本章编号、来源状态、章节契约，以及 `must_happen` / `must_not_happen`；
2. 上一章的结尾扰动与必要尾段，及下一章已承诺的承接点；
3. 与本章直接有关的 Canon、时间位置、地点规则和术语；
4. 出场人物的目标、恐惧、关系温度、资源/伤病、声纹、知识边界与禁止行动；
5. 相关物件的持有人、位置、可见性、代价与转移记录；
6. 相关伏笔、倒计时、未决问题、质量债与已标记的 `NOTICE` / `STALE` / `BLOCKED`；
7. 本项目风格约束与本轮目标。

不得把以下内容当成默认上下文：无关整卷正文、被标记为失效的台账、未经批准的提案、编辑评论本身、没有来源锚点的模型总结。

## 6. 章节契约的最低字段

正文前必须先有能约束文本的章节契约。若“主角想做什么”和“失败会失去什么”说不清，先停止写正文，重订契约。

```text
章节/版本/来源状态：
POV、时间、地点：
继承上一章的何种失衡：
可见目标：
最具体的失败代价：
核心阻力与强制选择：
must_happen：
must_not_happen：
人物状态 in/out、关系温度变化：
知识转移与必须保守的秘密：
物件/资源转移：
伏笔义务与回收窗口：
结尾扰动：
连续性风险与审稿阈值：
```

## 7. 故事、人物与世界约束

### 7.1 场景与因果

- 每章至少发生一次可见选择，并带来人物、社会或制度中的至少一项可见变化。
- 从具体现场开始：行动、物件、空间、身体、对话、劳动和代价优先于说明。
- 每个场景都应有压力源、信息延迟、转折与余味；结尾留下不稳定平衡，而不是解释性总结。
- 不能用巧合、万能技术、突发高层命令或未铺垫的角色知识替代因果。
- 新增事实必须改变行动、地位、风险、价格、关系或伏笔；否则删去或改写。

### 7.2 主题与文明逻辑

- 创造必须回答：谁创造、谁使用、谁受益、谁承担风险。
- 责任必须落实为记录、暂停、修复、赔偿、交接、退出或复核中的具体成本，不能只写宣言。
- 修复不等于复原；允许失败、空白、不可逆损失和未决问题留下。
- 连接不等于同化；地方、个体和智能都应有拒绝、退出、误解与重新协商的空间。
- 技术必须具有社会影响，不能只充当炫技背景或方便推进剧情的万能工具。

### 7.3 人物与智能

- 人物不得工具化或简单善恶化；每个重要人物要有社会位置、矛盾欲望、恐惧/羞耻、默认行动、声纹差异和不能触碰的话题。
- 周衡不得突然成为独裁者、为效率牺牲普通人，或放弃开放创造与第三种可能。
- 韩朔代表秩序与安全，不得被写成纯反派或彻底否定自由。
- 顾言代表效率、资本与规模，不得失去商业逻辑或变成单纯恶人。
- 404 是有限的经验、修复与关系协作者；不得成为万能 AI、单纯战斗机器、反叛机器、全知裁判或一切问题的终局答案。
- S-00 的成长必须伴随责任、关系、成本和可拒绝性；不得获得无限能力后失去约束。
- 事实真相、人物所知、读者所知必须分别记录；真实的事不等于所有人物都知道。

## 8. 文风与去机器感约束

- 总体气质：冷静、克制、宏大，但始终落在工业细节、人物选择和可感知的后果上。
- 不写“情绪标签先行”。用动作、身体反应、物件处理、沉默、失败习惯和他人反应替代“震惊、复杂、绝望、温柔”等抽象判断。
- 不使用摘要腔、整齐模板转场、均匀句长、同质对白、四字套语堆砌或章节末主题讲解。
- 对话必须改变关系温度、暴露信息差或迫使选择，不只是传递设定。
- 保留解释留白；紧张处允许延后 30%—50% 的因果信息，但不得故意隐瞒角色已经确认的关键事实。
- 结尾优先采用未完成动作、错误假设、物件、敲门、声音、债、代价或关系变化；避免“因此一切都明白了”的收束。
- 禁止单纯爽文升级、技术炫耀、机器统治捷径和黑白善恶二元化。

## 9. 生成、改写与审稿流程

### 9.1 正文生成

1. 读取最小上下文包并确认没有 `BLOCKED` 前提；
2. 写章节契约和场景卡；
3. 按“目标 → 阻力 → 选择 → 代价 → 变化”生成正文；
4. 标注为 `DRAFT`，保留来源、版本与字数目标；
5. 进行人物、世界观、时间线、物件/资源、伏笔、知识边界与去机器感检查；
6. 交由未参与该章写作的审读者或作者进行独立复审。

### 9.2 改写

先找故事压力、人物选择、因果链的三个最大问题，再决定：

- `PATCH`：局部修补，原章节契约仍然有效；
- `REWRITE`：按原契约重写关键段落或章节；
- `REPLAN`：契约、承接或下游计划本身失效，先重订再写；
- `BLOCKED`：与 Canon、时间线、知识边界或既有承诺冲突，停止改写并交作者决定。

改写不得把“修得更顺”误认为“已修好”。任何影响后续理解的改动都要登记影响范围。

### 9.3 最低检查

**可确定性检查**：标题/状态字段、章节路径、字数目标、角色在场、人物知识顺序、物件归属/转移、时间顺序、伏笔先后、来源哈希和重复台账更新。

**独立文学检查**：开篇拉力、现场清晰度、人物声纹、因果可信度、节奏、信息密度、情绪张力、主题是否由行动长出、结尾是否留下牵引。

正文生成者不得成为唯一验收者。项目约定字数目标时必须验证；当前默认参照为每章不少于 3000 字，除非对应章节契约另有批准。

## 10. 状态、台账与下游影响

1. `DRAFT` 正文只能更新候选审稿记录，不能更新 Canon 或持久事实台账。
2. 作者接受后，建立与正文版本绑定的持久变更清单，至少包含来源哈希、作者接受记录、证据锚点和以下变化：
   - 事实；
   - 人物状态与关系；
   - 知识边界；
   - 物件/资源；
   - 伏笔与回收；
   - 时间线与世界规则；
   - 质量债务。
3. 一旦接受的正文、Canon 或契约改变了后续依赖，逐项标记：
   - `NOTICE`：需知会或复核，暂不阻塞；
   - `STALE`：依赖旧版本，使用前必须修订或重新批准；
   - `BLOCKED`：与已接受变更冲突，不能继续使用。
4. 不能静默覆盖下游章节、提纲、检索摘要或图谱；先记录影响，再修复或重新批准。

## 11. 文档与交付物生成约束

- Markdown 是正文源；DOCX、PDF 和渲染图是交付物，不改变正文的 `DRAFT` / `ACCEPTED` / `CANON` 状态。
- 汇编时显式解析正文边界，支持项目实际使用的多种标题层级；内部 `####` 小标题后的首段必须做回读验证。
- 至少核验章节数、标题、每章首尾段、随机正文样本、目录/分页、空白页、最终文件哈希。
- 若没有完成实际渲染或视觉检查，只能报告结构/文本验证通过，不得声称版式或成品已被视觉验收。
- 任何交付物必须标明来源版本和当前文学状态；“正文已汇编完成”不等于“作者已验收”。

## 12. 每次执行前的快速清单

- [ ] 任务类型、范围和目标是否明确？
- [ ] 是否读取了相关 Canon、契约、上一章结尾、人物状态、时间线、物件与伏笔？
- [ ] 是否存在 `TBD`、`STALE` 或 `BLOCKED` 前提？
- [ ] 本章是否有清楚的可见目标、具体代价、强制选择和结尾扰动？
- [ ] 是否避免了万能技术、未铺垫知识、口号化主题和人物工具化？
- [ ] 是否完成去机器感与连续性检查？
- [ ] 是否保持 `DRAFT`，并由独立审读/作者处理验收？
- [ ] 若影响下游，是否记录了 `NOTICE` / `STALE` / `BLOCKED`？
