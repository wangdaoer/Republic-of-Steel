# 小说创作运行层接入说明

状态：`DRAFT / WORKFLOW`

## 适用范围与当前状态

本文只为《钢铁共和国》现有工程补充一条可追踪的文学复审与验收路径，不改写正文、不重定 Canon，也不把模板或审稿意见自动写入台账。

项目计划记录四卷、240章正文已形成，整体标记为 `COMPLETE / DRAFT`；卷级和逐章资料中还可见 `DRAFT / POLISH_PASS_1 / FINAL_REVIEW_REQUIRED`、`REVIEW_REQUIRED` 等状态。`COMPLETE` 说明规划范围内的正文和结构资产已具备，**不等于**正文已由作者验收。除非有明确的作者接受记录，正文仍按其来源中的 `DRAFT` 或待复审状态处理，不得改称 `ACCEPTED` 或 `CANON`。

若状态文件之间的范围、版本或结论不一致，复审报告必须登记“状态待确认（`TBD`）”：列出冲突来源、各自状态、适用章节/卷和待作者决定的问题。不得以较新的文件、较长的说明或模型推断静默裁决。

## 权威顺序

处理任何一章时，证据和指令按以下顺序取用：

1. `canon/` 中作者确认的 Canon；
2. 已批准的章节契约、卷级大纲与人物、时间线、伏笔、事实等台账；
3. 标有状态的正文草稿与 Prompt 模板；
4. 新建议、审稿意见和重构设想（默认 `PROPOSAL`）。

下层材料不能推翻上层材料。草稿中的事件、提纲义务、模型摘要和审稿建议都是待核证材料；发现冲突时保留证据，标为 `REVIEW`、`BLOCKED` 或 `TBD`，等待作者决定。

## 当前默认路由

本项目四卷正文已建立。除非作者明确要求续写、新增章节、重构或改写，当前默认工作是对**指定章节进行独立文学复审**，而不是继续批量生成正文。

推荐路由如下：

```text
指定章节 + 最小上下文包
        -> 独立文学复审
        -> PASS / REVIEW / BLOCKED
        -> 作者决定是否修订、重订契约或接受
        -> 仅在作者接受后记录变更清单与下游影响
```

复审者不应自行把草稿改标为 `ACCEPTED`；如复审者也是该章草稿的生成者，应在报告中注明，仍由作者承担最终验收。

## 单章最小上下文包

只加载缺失后会使本章判断失真的材料，并记录使用的版本：

1. 章节编号、正文版本、当前来源状态与本章章节契约（含必须/禁止事项）；
2. 上一章的结尾扰动、下一章已经承诺的承接点；
3. 本章相关 Canon、时间线位置、地点和活动中的世界规则；
4. 出场人物的当前目标、关系、伤病/资源、声纹和知识边界；
5. 卷内章节索引、伏笔表、事实/人物/时间线台账中与本章直接相关的条目；
6. 本章涉及的物件、资源、承诺、秘密与不可越过的边界；
7. 本项目的风格约束：冷静克制、工业细节、责任后果、非二元化人物，以及本次复审目标。

不要把整部作品、无关章节或未经批准的 `PROPOSAL` 当作默认上下文。远处章节只有在承担伏笔、回收或明确承接义务时才加入。

## 独立文学复审结论

- `PASS`：当前证据下未发现阻塞性 Canon、连续性或文学问题；仅代表本次复审通过，**不等于**作者验收或状态升级。
- `REVIEW`：存在可讨论的风险、质量债务、证据不足或需要局部修订的问题；保留问题、证据与建议。
- `BLOCKED`：与 Canon、时间线、人物知识边界、既有承诺或关键因果明确冲突；停止静默改写，先交作者决定。

作者明确接受某个正文版本后，才可将该版本标记为 `ACCEPTED`，并以该版本为依据回写事实、人物、关系、知识、资源、伏笔和时间线台账。没有作者接受记录时，即使结论是 `PASS`，该章仍维持原有状态。

## 作者接受后的持久变更清单

每次作者接受正文或 Canon 改动后，必须保存一份与章节版本绑定的“变更清单”。它只记录会影响后续创作或解释的持久变化，而不是把全部审稿意见重抄一遍。

```text
章节与版本：
接受版本标识/哈希：
作者接受记录：
来源与证据锚点：

持久变更：
- 事实：
- 人物状态与关系：
- 知识边界：
- 物件/资源：
- 伏笔与回收：
- 时间线/世界规则：

质量债务（如有）：
下游影响：
- 文件或章节：
  影响：NOTICE / STALE / BLOCKED
  原因、证据与下一步：
```

若接受的文本、Canon 或章节契约改变了后续依赖，必须逐项登记受影响的章节契约、卷级大纲、检索摘要、台账和后续章节，并标记：

- `NOTICE`：需要知会或复核，但暂不阻塞；
- `STALE`：依赖旧版本，使用前必须修订或重新批准；
- `BLOCKED`：与已接受变更冲突，不能继续使用。

不得静默覆盖下游文件，也不得用未接受的草稿更新台账。状态待确认的材料先作为问题保留，待作者决定后再进入变更清单。
